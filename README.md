# Визуализатор графа зависимостей пакетов Cargo

Практическая работа № 2, вариант 9. Этап 2 — сбор данных.

## 1. Общее описание

Инструмент командной строки (CLI) для анализа и визуализации графа
зависимостей пакетов менеджера Cargo (язык Rust). Готовые менеджеры
пакетов и сторонние библиотеки для получения зависимостей
не используются, только стандартная библиотека Python.

Все параметры задаются в конфигурационном файле формата XML.
На этом этапе программа читает конфигурацию, по URL-адресу репозитория
находит новейшую версию заданного пакета и выводит его прямые
зависимости.

Код находится в каталоге `src`, тесты — в `tests`.

## 2. Функции и настройки

### Запуск

```text
python src/main.py [ПУТЬ_К_КОНФИГУРАЦИИ]
```

Если путь не указан, читается `config.xml` из текущего каталога.

### Параметры конфигурации

Корневой тег — `<config>`. Внутри задаются параметры:

- `package` — имя анализируемого пакета. Имя пакета Cargo (латинская
  буква, затем буквы, цифры, `_`, `-`); в тестовом режиме — большие
  латинские буквы.
- `repository` — URL-адрес репозитория (начинается с `http://` или
  `https://`) или, в тестовом режиме, путь к файлу тестового
  репозитория (файл должен существовать).
- `test_mode` — режим работы с тестовым репозиторием: `true` / `false`
  (также `yes` / `no`, `1` / `0`).
- `output_file` — имя файла с изображением графа, оканчивается на `.svg`.
- `ascii_tree` — режим вывода зависимостей в виде ASCII-дерева:
  `true` / `false`.
- `max_depth` — максимальная глубина анализа зависимостей, целое
  число от 1.
- `filter` — подстрока для фильтрации пакетов. Необязательный
  параметр; латинские буквы, цифры, `_`, `-`.

Пример (`config.xml`):

```xml
<config>
    <package>serde_json</package>
    <repository>https://index.crates.io</repository>
    <test_mode>false</test_mode>
    <output_file>serde_json.svg</output_file>
    <ascii_tree>true</ascii_tree>
    <max_depth>2</max_depth>
    <filter></filter>
</config>
```

### Обработка ошибок

Программа проверяет все параметры сразу и выводит полный список
найденных ошибок, после чего завершается с кодом 1. Обрабатываются:

- отсутствующий файл конфигурации, повреждённый XML, неверный
  корневой тег;
- отсутствующий или пустой обязательный параметр;
- неизвестный параметр и повторно заданный параметр;
- недопустимое имя пакета (отдельные правила для тестового режима);
- URL без `http://` / `https://`, отсутствующий файл тестового
  репозитория;
- значение `test_mode` и `ascii_tree`, не являющееся логическим;
- имя файла изображения не с расширением `.svg`;
- глубина, не являющаяся целым числом или меньше 1;
- недопустимые символы в подстроке фильтра.

Примеры ошибочных конфигураций лежат в каталоге `configs/errors`.

### Получение зависимостей (формат Cargo)

Данные берутся из индекса реестра пакетов Cargo в разреженном
(sparse) формате — так же, как это делает сам Cargo. По умолчанию это
`https://index.crates.io`. Для каждого пакета в индексе есть текстовый
файл, путь к которому строится по имени:

- 1 или 2 символа: `1/a`, `2/ab`;
- 3 символа: `3/s/syn`;
- 4 и более: первые две буквы, следующие две, имя —
  `se/rd/serde_json`.

Каждая строка файла — JSON-описание одной версии пакета с полем `deps`.
Файл скачивается модулем `urllib` стандартной библиотеки, менеджеры
пакетов и сторонние библиотеки не используются.

Правила выбора данных:

- берётся новейшая версия по правилам semver (`1.10.0` новее `1.9.0`);
- отозванные (yanked) версии пропускаются, pre-release версии
  используются, только если других нет;
- прямыми зависимостями считаются обычные (`normal`) обязательные
  зависимости; dev- и build-зависимости, а также необязательные
  (optional) пропускаются;
- для переименованных зависимостей выводится настоящее имя пакета.

Ошибки репозитория: пакет не найден (HTTP 404, 410, 451), другие
ошибки HTTP, недоступный адрес, некорректные данные индекса. Режим
тестового репозитория на этом этапе ещё не поддерживается и выдаёт
сообщение об ошибке.

## 3. Сборка и тесты

Сборка не нужна, требуется Python 3.8 или новее.

Запуск:

```sh
sh run.sh config.xml
```

```bat
run.bat config.xml
```

Тесты:

```sh
python -m unittest discover -s tests -v
```

Тесты не обращаются к интернету: для проверки HTTP-запросов они
поднимают локальный сервер с файлами в формате индекса crates.io.

Демонстрация обработки ошибок для всех параметров:

```sh
sh scripts/demo_errors.sh
```

```bat
scripts\demo_errors.bat
```

Прямые зависимости реальных пакетов (`config.xml` и
`configs/real_*.xml`, нужен доступ в интернет):

```sh
sh scripts/demo_direct.sh
```

```bat
scripts\demo_direct.bat
```

## 4. Примеры использования

Прямые зависимости пакета (вид вывода; версия и список зависят от
текущего состояния crates.io):

```text
$ python src/main.py config.xml
Пакет: serde_json 1.0.x
Прямые зависимости (N):
  itoa ^1.0
  memchr ^2
  ryu ^1.0
  ...
```

Пакета нет в репозитории:

```text
$ python src/main.py configs/real_missing.xml
Ошибка получения зависимостей:
  - пакет не найден в репозитории: https://index.crates.io/no/-s/no-such-crate-kola-su
```

Ошибки во всех параметрах сразу:

```text
$ python src/main.py configs/errors/all_errors.xml
Ошибка конфигурации:
  - <package>: недопустимое имя пакета Cargo '???'
  - <repository>: URL должен начинаться с http:// или https://, получено 'ftp://index.crates.io'
  - <output_file>: имя файла должно оканчиваться на .svg, получено 'graph.jpg'
  - <ascii_tree>: ожидается true или false, получено 'sometimes'
  - <max_depth>: глубина должна быть не меньше 1, получено -3
  - <filter>: подстрока может содержать только латинские буквы, цифры, '_' и '-', получено 'serde json'
```
